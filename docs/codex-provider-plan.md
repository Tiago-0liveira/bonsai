# Codex provider + provider marks: implementation plan

Status: plan, 2026-10-11. Base: **`origin/main` @ `56c64b0`** (Merge #67 `feat/bonsai-web`).
Codex CLI checked: `codex-cli 0.162.1` (local), official docs at `learn.chatgpt.com/docs/auth`
and `learn.chatgpt.com/docs/developer-commands?surface=cli`, and the app-server JSON schema
generated by `codex app-server generate-json-schema`.

## Goal

1. **Codex** (`codex`) becomes the third real agent provider next to Antigravity and Claude
   Code, at feature parity: profiles (accounts) created from the CLI, several profiles at
   once, several concurrent sessions per profile, CLI `bonsai agent run`, web Start agent →
   live terminal, stop/reattach, model suggestions, launch options, auth/identity display,
   usage in `bonsai agent usage`. No test needs a real login or the network.
2. **Real provider marks everywhere.** Codex and Antigravity get their logos (Claude already
   has one); letters (`AG`, `CX`, `GM`) and generic `Bot`/`Sparkles` stand-ins disappear
   from every surface that identifies a provider.

## 1. Decisions

| Topic | Decision |
| --- | --- |
| Isolation | Each profile owns a persistent Bonsai-managed **`CODEX_HOME`** = `<AccountDir>/home`, shared by all its sessions. Same model as Claude's `CLAUDE_CONFIG_DIR`; no Antigravity-style credential copy/materialize/reconcile (Codex rotates refresh tokens, copies would log each other out). |
| Credential store | Force `cli_auth_credentials_store="file"`: written into the profile `config.toml` **and** passed as `-c` on every invocation. Credentials then always live in `$CODEX_HOME/auth.json` on every OS (macOS Keychain never mixes profiles; identity/usage readable). |
| Auth modes | `chatgpt` (default; `codex login` browser), `device` (`codex login --device-auth`; WSL/SSH/headless), `api-key` (`codex login --with-api-key`, key piped from `--token-stdin` or hidden prompt). Codex writes `auth.json` itself; **Bonsai never stores a Codex secret**. |
| Seeding | One-time allowlisted copy from the user's `~/.codex` (or host `CODEX_HOME`): filtered `config.toml`, `AGENTS.md`, `prompts/`, `skills/`, `rules/`. `--no-seed` / `--seed-from` as Claude. |
| Shared app-server daemon | Codex 0.162 attaches TUIs to a shared background daemon by default. **Launch with `--no-daemon`** so each Bonsai session owns its whole process tree (stop kills everything; `BONSAI_AGENT_SESSION_ID` correct in tool shells; no orphan daemons on profile removal). Phase 0 step 6 re-checks the same-account refresh race; switch only if it fails. |
| Launch options | Model (suggested from `model/list`), reasoning effort (**per model**), permissions preset (Read only · Auto · Full access · Bypass), prompt. |
| Launch UI | Providers **declare their launch fields** (`LaunchSchema`); the dialog renders them generically. Removes every `isClaude` branch instead of adding `isCodex` ones. |
| Usage | `codex app-server` stdio JSON-RPC → `account/rateLimits/read`. Versioned, schema-published protocol; any token refresh is done by Codex itself (safe, unlike Claude's undocumented endpoint where Bonsai must never refresh). |
| Identity | Email + plan from the `id_token` JWT claims in `auth.json` (no network, no process). Auth status from `codex login status` exit code (5 s timeout, 60 s cache). |
| Marks | One `ProviderLogo` component with inline, pinned path data. Codex: LobeHub `codex.svg` (MIT, mono, `currentColor`). Antigravity: LobeHub `antigravity.svg` mono path (MIT) filled with **one** small linear gradient in Google colours (the official colour SVG uses 11 blur filters and a mask: too heavy for many canvas badges). Claude: existing Simple Icons path (CC0). Gemini: Simple Icons `googlegemini` (CC0), display-only. Unknown provider: lucide `Bot`. Nothing fetched at runtime. |
| Platforms | Linux/WSL full. macOS: login, launch, usage (file store forced). Native Windows: CLI works; web terminal stays unsupported (existing ConPTY gap). |

## 2. Codex CLI facts the design relies on

- **`CODEX_HOME`** (default `~/.codex`) holds everything: `config.toml`, `auth.json`,
  `sessions/`, `history.jsonl`, SQLite state (`state_5.sqlite`, `logs_2.sqlite`, …),
  `skills/`, `rules/`, `plugins/`, `app-server-*`. Docs: "`file` stores credentials in
  `auth.json` under `CODEX_HOME`". Multiple accounts are not documented ⇒ Phase 0 proves
  isolation.
- `cli_auth_credentials_store = file | keyring | auto | ephemeral`; admins can enforce it.
- `auth.json` keys (observed, names only): `auth_mode`, `OPENAI_API_KEY`,
  `tokens{access_token, account_id, id_token, refresh_token}`, `last_refresh`.
- Auth: `codex login`, `--device-auth`, `--with-api-key` (stdin), `--with-access-token`
  (enterprise; out of scope), `codex logout`, `codex login status` → exit 0
  `Logged in using ChatGPT` / exit 1 `Not logged in` (observed with an empty home).
- Interactive flags (0.162.1 `--help`): `[PROMPT]` positional, `-m/--model`, `-c key=value`
  (TOML), `-p/--profile`, `-s/--sandbox read-only|workspace-write|danger-full-access`,
  `-a/--ask-for-approval on-request|never` (schema also `untrusted`),
  `--dangerously-bypass-approvals-and-sandbox`, `-C/--cd`, `--add-dir`, `--search`,
  `--no-alt-screen`, `--no-daemon`. Effort: `-c model_reasoning_effort="<e>"`.
  **No `--session-id`, no `--name`**; resume is `codex resume <uuid>`.
- Efforts are per model (`codex debug models --bundled`): e.g. `gpt-6.1-sol`
  `low…ultra`, `gpt-6-luna` `low…max`, `gpt-5.5` `low…xhigh`; some models are `hide`.
- App-server (stdio JSON-RPC): `initialize`; `account/read` →
  `{account:{type:"chatgpt",email,planType}|{type:"apiKey"}, requiresOpenaiAuth}`;
  `account/rateLimits/read` → `rateLimits{primary,secondary{usedPercent,windowDurationMins,resetsAt}, planType, credits, limitName}`
  + `rateLimitsByLimitId`; `model/list` → `{id, displayName, hidden, isDefault,
  supportedReasoningEfforts[{reasoningEffort,description}], defaultReasoningEffort}`;
  `account/login/start` (`chatgpt` → `authUrl`, `chatgptDeviceCode`, `apiKey`) enables a
  future web login.
- Daemon socket: `$CODEX_HOME/app-server-control/app-server-control.sock` →
  `/tmp/codex-daemon-<uid>/<sha256>` (likely per home; irrelevant with `--no-daemon`).
- Env that changes identity/behaviour: `OPENAI_API_KEY`, `OPENAI_BASE_URL`,
  `CODEX_API_KEY`, `CODEX_ACCESS_TOKEN`, `CODEX_HOME`, `CODEX_SANDBOX*`,
  `CODEX_THREAD_ID`… Keep: `CODEX_CA_CERTIFICATE`, `SSL_CERT_FILE` (corporate TLS).
- New directories show a "trust this folder" screen and write `[projects."<path>"]` into
  `config.toml`; every worktree is a new path (Phase 0 step 8).
- `CODEX_HOME` under `/tmp` prints a "refusing to create helper binaries" warning: the
  version probe uses a scratch dir under the Bonsai cache dir, not `os.TempDir()`.

### Phase 2 — generic launch-field schema (backend + web, no Codex)

**Backend**

```go
type LaunchOptions struct {
    Model, Prompt, DisplayName string
    FullAccess     *bool  // Antigravity
    PermissionMode string // Claude
    Effort         string // Claude, Codex
    Sandbox        string // Codex: read-only|workspace-write|danger-full-access|bypass
    Approval       string // Codex: untrusted|on-request|never
}

type LaunchField struct {
    ID       string        `json:"id"`        // matches the request field name
    Label    string        `json:"label"`
    Kind     string        `json:"kind"`      // "select" | "toggle"
    Options  []FieldOption `json:"options,omitempty"`
    PerModel bool          `json:"per_model,omitempty"` // values come from ModelOption.Efforts
    Help     string        `json:"help,omitempty"`
}
type FieldOption struct {
    Value string `json:"value"`; Label string `json:"label"`
    Tone  string `json:"tone,omitempty"` // "danger": bypass / full access
    Set   map[string]string `json:"set,omitempty"` // presets: {"sandbox":"…","approval":"…"}
}
type LaunchSchema interface{ LaunchFields() []LaunchField }

type ModelOption struct { …existing…
    Efforts       []string `json:"efforts,omitempty"`
    DefaultEffort string   `json:"default_effort,omitempty"`
    Default       bool     `json:"default,omitempty"`
}
```

- Antigravity implements `LaunchSchema` (`full_access` toggle, danger tone + its current
  help text). Claude implements it (`permission_mode` select incl. Bypass danger tone,
  `effort` select). Argv of both stays **byte-identical** (existing golden tests).
- `localapi`: `GET /api/agents/providers` adds `launch_fields`; `POST …/agents` accepts
  `sandbox`, `approval` (strict decode, ≤32 chars, included in the idempotency fingerprint);
  unknown/unsupported fields → `400 invalid_launch_options` through `LaunchValidator`.
- Move the known-provider table (`agents.go:60`) next to the registry
  (`agents.KnownProviders`) so localapi tests no provider ID.

**Web**

- `api/agents.ts`: `AgentCapability.launch_fields`, `AgentModel.efforts/default_effort/default`;
  `startAgent` body gets `options: Record<string,string|boolean>` flattened into the JSON.
- `StartAgentDialog.tsx`: a `LaunchFields` sub-component renders select/toggle fields from
  the schema (`BonsaiSelect`, existing switch), danger tone → warn tint + help note,
  `per_model` → values from the chosen model's `efforts` (falls back to the field's own
  options when the model is free text or unlisted). State is one `options` object reset on
  provider change. Fingerprint = `{providerId, worktreeId, accountId, name, model, workType, prompt, options}`.
  Footer summary = provider label + selected option labels. Model placeholder from the
  provider (`default` model label, else "Use profile default").
- `stores/bonsai.ts` `createAgent`: sends `options` as given; the `=== 'claude'` branch goes.
- `types/index.ts`: drop the Claude-only comments; `AgentProviderId` stays
  `'antigravity' | 'claude'` until Phase 5.

## Risks

| Risk | Mitigation |
| --- | --- |
| Same-login sessions race on refresh-token rotation | Phase 0 step 6; Bonsai never writes `auth.json`; API-key mode race-free; daemon fallback documented. |
| Inherited env switches identity | `CODEX_`/`OPENAI_` scrub + polluted-env tests; CA cert preserved explicitly. |
| Admin forces keyring storage | `DescribeAccount` warning; launch still works; identity/usage degrade to unknown. |
| Codex 0.x flags change fast | `MinVersion`; argv in one function with goldens; no `--strict-config`. |
| App-server protocol drift | Isolated client, tolerant decoding, fixtures from Phase 0, soft failures. |
| Seeded config leaks keys or host paths | Key filter + deny globs; `--no-seed`. |
| Trust screen per worktree | Phase 0 step 8; worst case shown once per worktree per profile. |
| Logos inflate first-screen JS / slow canvas | Mono paths, one gradient, no filters; `bundle:check`; render-isolation spec. |
| Logo licensing | Pinned MIT/CC0 sources, NOTICE, identification-only use. |
